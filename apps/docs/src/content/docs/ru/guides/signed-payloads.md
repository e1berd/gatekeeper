---
title: Подписанные payload'ы
description: Вход по данным, которые провайдер подписал сам, — например Telegram Mini App.
---

Не всякий провайдер водит браузер по редиректам. Telegram Mini App отдаёт странице строку
`initData`, подписанную токеном бота: доказать личность — значит проверить подпись, а не гонять
браузер через две точки входа.

`auth.verifySignedPayload` — этот единственный вызов. Он принимает блоб, проверяет его и возвращает
тот же результат аутентификации, что и любой другой способ входа.

```yaml
signedPayload:
  telegram:
    secret: '123456:AA…' # токен бота
    maxAgeSeconds: 86400
```

Провайдеру, которого здесь нет, отказывают с `PROVIDER_NOT_CONFIGURED` — включение провайдера это
изменение конфигурации, а не кода.

## Что проверяется

Для Telegram —
[схема Mini Apps](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app):
HMAC над отсортированной data-check-string, ключ которой сам является HMAC от токена бота. Сравнение
константное по времени, а `auth_date` обязан попадать в окно `maxAgeSeconds` — без него
перехваченный payload работал бы вечно.

Любая неудача — нет хэша, payload отредактирован после подписи, `auth_date` протух, пользователя нет
— возвращается как `INVALID_TOKEN`. Какая именно, вызывающему не сообщают: клиент, умеющий отличить
плохую подпись от протухшей, умеет этим и зондировать.

## Личность

Payload называет аккаунт у провайдера, поэтому личность разрешается так же, как при социальном
входе: знакомая связка провайдер + идентификатор пускает своего пользователя, незнакомая создаёт
аккаунт.

Telegram не сообщает адрес почты, поэтому по этому пути ничего не связывается по email, и у
создаваемого аккаунта его нет. Это намеренно: связывание по адресу, который провайдер не подтвердил,
отдало бы аккаунт любому, кто может вписать себе чужой адрес.

## `initData` — входной билет, а не сессия

Обменяйте его один раз, сохраните полученные токены и обновляйте их, как любую другую сессию. Mini
App, отправляющий `initData` на каждый запрос, не остаётся залогиненным, а заново аутентифицируется.
